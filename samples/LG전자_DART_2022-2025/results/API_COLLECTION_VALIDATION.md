# OpenDART 실제 수집 검증 결과

검증일: 2026-10-11 (한국 시간). 모의 입력을 사용하지 않고 프로젝트 `.env`의 인증키로 실제 OpenDART를 호출했습니다.
API 키는 이 문서와 결과 파일에 기록하지 않았습니다.

## 소량 수집 및 재실행

```sh
python dart_collector.py --start 20250301 --end 20250331 --types A --max-documents 3 --financial-years 2024 --report-codes 11011
```

첫 실행: 공시 1건, 원문 1건, 재무 계정 30개 저장, API 호출 4회, 오류 없음.
두 번째 실행: 신규 공시·원문·재무 저장 0건, 원문 1건과 재무 조회 1개 건너뜀, API 호출 1회, 오류 없음.
수집 공시는 LG전자 사업보고서 (2024.12), 접수번호 `20250317001029`입니다.

## 확인한 내용

- LG전자 고유번호 `00401731`, 종목코드 `066570`을 실제 기업 목록에서 조회했습니다.
- 저장된 기업·공시·재무 컬럼을 보존된 원본 항목과 대조했습니다.
- 두 번째 실행에서 공시·원문·재무 건수가 증가하지 않았습니다. 접수번호 중복 그룹은 0개입니다.
- 재무 16개 조회 범위가 모두 정상 수집됐습니다. `013` 재무 자료 없음은 발생하지 않았습니다.
- SQLite `integrity_check` 결과는 `ok`입니다.
- 원문 149건의 ZIP 해시와 해제 파일 157개의 bytes가 ZIP 내부 원본과 일치했습니다.
- 호출 한도에 실제로 도달시키는 테스트는 수행하지 않았습니다.

## 원문 미제공 및 XML 파싱 주의사항

다음 거래소공시 4건은 API가 `014`(원문 파일 없음)를 반환했습니다.

- `20221007800307`: [첨부정정]연결재무제표기준영업(잠정)실적(공정공시)
- `20231110800817`: [첨부정정]지속가능경영보고서등관련사항(자율공시)
- `20240909800282`: [첨부정정]지속가능경영보고서등관련사항(자율공시)
- `20250725800440`: [첨부정정]연결재무제표기준영업(잠정)실적(공정공시)

목록과 `document_status='failed'`, 오류 사유는 보존했습니다. 두 번째 실행에서도 동일 응답을 확인했습니다.
두 실행 모두 `completed_with_errors`와 종료 코드 1을 반환했습니다. 모든 원문을 확보했다고 주장할 수 없습니다.

소량 수집한 사업보고서 본문 및 두 첨부 XML은 엄격한 lxml XML 파서에서
`xmlParseEntityRef: no name` 오류가 발생했습니다. 복구 모드에서는 `DOCUMENT` 루트를 읽었지만,
이것으로 본문·표 정규화 정확성을 검증한 것은 아닙니다.
후속 모듈은 원문 오류 처리와 추출 내용 대조가 필요합니다. 원본 XML은 변경하지 않았습니다.

## 후속 모듈에 전달할 자료

- `data/dart.db`: 공시 목록·기업 목록·원문 경로·재무 계정
- `data/raw/`: 원문 ZIP과 XML
- `docs/COLLECTOR.md`: DB 구조와 읽는 방법

DB와 원문은 Git에서 제외됩니다. 같은 상대 폴더 구조로 함께 전달해야 합니다.
후속 정규화·변화 탐지·CrewAI 실행과 과제의 실제 3개 사례 평가는 이 검증에 포함하지 않았습니다.
