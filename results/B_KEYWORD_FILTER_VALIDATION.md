# B 키워드 오탐 개선 검증

## 변경 목적

정기보고서에서 `중단`, `분할`, `합병` 키워드가 실제 사건이 아닌 회계 항목명·회사 연혁에서도 다수 탐지되어
CrewAI Task 1이 이를 실제 사건으로 잘못 판정하는 문제를 줄였다.

## 변경 내용

- `change_detector.py`
  - `중단영업 당기순손실`, `중단사업손익` 등 재무 표의 계정/열 이름 속 `중단`을 후보에서 제외.
  - `2002년 ... 인적분할하여 설립`, 납입자본의 과거 분할·합병 이력 등 회사 연혁 문맥을 후보에서 제외.
  - 제외된 건수는 `needs_verification`의 `KEYWORD_EXCLUDED`로 남김.
  - 부정문(`합병 계획 없음`)과 일반 사업 설명은 Program에서 삭제하지 않고 Task 1이 실제 사건 여부를 판단하도록 유지.
- `crew.py`
  - Task 1 Description에 실제 사건/비사건 판단 기준과 예시 추가.
  - 실제 사건은 이번 공시에서 새로 결정·발생한 중단·분할·합병·양수·신규사업으로 한정.
  - 회계 항목명, 과거 연혁, 일반 사업 설명, 부정문은 `is_actual_event=false`; 불명확하면 `null`.

## 단위 테스트

`tests/test_role_b.py`에 키워드 제외 규칙 테스트를 추가했다.

```text
Ran 14 tests
OK
```

검증 예:
- `중단영업 당기순손실 | (5,485)` → Program 키워드 후보에서 제외
- `2002년 ... 인적분할하여 설립` → Program 키워드 후보에서 제외
- `현재 합병 계획은 없습니다.` → 후보는 유지, Task 1에서 실제 사건 아님(false)으로 판단
- `2026년 A사업의 영업을 중단하기로 결정했습니다.` → 후보 유지

## 실제 LG전자 일반 사례 검증

대상: `20251114001332`, LG전자 `분기보고서 (2025.09)`

### 수정 전

- B가 전달한 키워드 근거: 14건
  - 신규사업 3, 중단 3, 분할 3, 합병 3, 양수 2
- `KEYWORD_EVIDENCE_TRUNCATED`: 3종(중단/분할/합병)
- 기존 CrewAI 실행에서 `중단영업 당기순손실`과 2002년 인적분할 연혁이 `실제 사건`으로 잘못 판정됨.

### 수정 후 B 재실행

- B가 전달한 키워드 근거: 12건
  - 신규사업 3, 중단 3, 분할 2, 합병 2, 양수 2
- `KEYWORD_EXCLUDED`
  - 중단: 회계 항목명 151건 제외
  - 분할: 과거 회사 연혁 10건 제외
  - 합병: 과거 회사 연혁 2건 제외
- `KEYWORD_EVIDENCE_TRUNCATED`: 중단 1종만 남음(유효 후보 8건 중 앞 3건 전달)
- 회계 항목과 과거 연혁이 Agent 입력 전에 대량 제거되어 실제 사건 판정 입력이 정제됨.

## PPT용 수정 전/후 요약

| 구분 | 수정 전 | 수정 후 |
| --- | --- | --- |
| `중단` 탐지 | `중단영업 당기순손실` 등 회계 계정도 사건 후보 | 회계 항목명 151건 Program 단계 제외 |
| `분할/합병` 탐지 | 2002년 설립·납입자본 과거 이력도 사건 후보 | 과거 회사 연혁 분할 10건·합병 2건 제외 |
| 제외 이력 | 확인 불가 | `KEYWORD_EXCLUDED`로 제외 이유·건수 보존 |
| Task 1 판단 기준 | 부정문 정도만 명시 | 이번 공시에서 새로 결정·발생한 사건만 true, 회계/연혁/설명/부정문은 false |
| 기대 효과 | 키워드 존재 자체를 사건으로 오판 가능 | Program 필터 + Agent 문맥 판단의 2단계 오탐 방지 |

> 실제 LLM의 Task 1 판정 변화는 OpenAI API 키가 설정된 개발 환경에서 `main.py`로 동일 사례를 재실행하여 최종 확인한다.
