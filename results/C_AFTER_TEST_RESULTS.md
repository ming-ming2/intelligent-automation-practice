교수 코멘트(수치 파싱을 Agent가 호출) 반영 상태: 도구 3개(`lookup_financial_change`, `lookup_amount_change`, `parse_amount_text`)는
구현돼 있고, Crew 안에서 Agent가 도구를 호출해 Program 값을 받는 흐름은 테스트로 확인했다. 그러나 실제 gpt-4o-mini는
세 번의 실행(9건) 모두 도구를 호출하지 않았다. CrewAI의 도구 사용은 모델이 고르는 방식(`tool_choice=auto`)이라 강제할 수 없다.
그래서 공시 수치의 정확도는 Agent의 도구 호출 여부와 관계없이 Program이 보장하도록 했다(Program 결과 요약 제공 + CHANGE 수치 규칙 + 대조).
"도구를 제공해도 모델이 쓰지 않을 수 있으니, 사실 정확도는 Program 쪽에서 보장해야 한다"는 것이 이번 테스트에서 확인한 점이다.

## 4. Human-in-the-Loop 정리

### 담당자 검토 단계

`--no-review` 없이 실행하면 아래 순서로 진행한다 (`main.py`).

1. Agent 3개가 보고서 초안을 만든다.
2. Program이 대조 결과를 화면에 띄운다: FACT 인용 원문 대조, CHANGE 수치 보정 기록, 보고서 증감 방향 대조.
3. 담당자가 보고서와 경고를 보고 승인 / 보류 / 반려를 고른다.
   - 승인: 최종 중요도(높음·중간·낮음·보류)와 의견 입력.
   - 반려: 사유 선택 → 근거 오류는 공시 사실 추출부터, 비교·해석 오류는 사업 변화·영향 분석부터, 형식 오류는 보고서 작성만 재실행 (최대 3회). 수정 지시는 해당 Agent 지시서의 '재작업 요청' 칸으로 전달된다.
4. 회차별 결과 파일과 판단 이력(`data/review.db`의 `review_history`)이 저장된다. 중요도가 낮은 공시도 저장한다.

### 사람이 봐야 하는 이유 (이번 테스트에서 실제로 나온 사례)

- 표 오독·인용 변형: 복잡 사례에서 Agent가 표 이름을 붙여 `처분내역_처분금액(원)`으로 인용했다. Program은 "원문과 다르다"까지만 알려 주고,
  금액이 맞는지, 정정 전후 중 어느 값인지는 사람이 원문 표를 보고 확인해야 한다. 같은 사례에서 Program은 정정 전후 금액이 한 표에 있어 값을 확정하지 못했다.
- 문장 의미 변형: 일반 F1은 인용은 원문 그대로인데 문장은 "중단하였습니다"를 "중단하기로 결정하였다"로 바꿨다.
  복잡 F2는 LG전자 자기자본을 "LG ELECTRONICS INDIA LIMITED의 자기자본"이라고 썼다. 숫자가 맞아서 Program 대조로는 잡히지 않는다.
- 보고서 단계에서 생긴 내용: 복잡 보고서의 키워드 절에 Agent 판정에 없던 "(처분금액) 실제 사건"이 들어갔다. 최종본은 사람이 읽고 확인해야 한다.
- 사건 시점 판단: 2024년 배터리팩 영업 중단을 '이번 공시의 실제 사건'으로 볼지는 기준 해석의 문제라 담당자가 판단해야 한다.
- 연결/별도 혼동: 개선 전 보고서는 연결 순이익 +49.1%를 '감소'로 썼다(별도 -66.5%와 혼동 추정). 개선 후에는 Program 대조가 잡지만,
  어느 기준으로 보고할지는 사람이 정한다.
- 해석의 타당성: "IPO 구주 매출이 경쟁 압력" 같은 해석은 형식상 문제가 없어 Program이 걸러내지 못한다. 직전 실행에서는 "경쟁사 순이익 증가가 삼성전자에도 긍정적"이라고 썼다가
  이번 실행에서는 "위협 요소"라고 썼다. 같은 입력에도 해석 방향이 바뀔 수 있다.
- 중요도는 전략 판단: 인도법인 지분 처분(약 1.86조 원)은 Program의 변화 탐지 기준(금액 ±20%, 재무 ±15%)으로는 '비교 불가'일 뿐이지만,
  경쟁사의 인도 시장 전략 측면에서는 중요할 수 있다. 중요도는 Program·AI가 정하지 않고 담당자가 정한다.
- 반려 피드백의 한계: 정엽님 기록대로, 4주차 일반 사례에서 "중단영업은 회계 항목"이라는 반려 지시를 두 번 줘도 키워드 판정이 바뀌지 않았다.
  사람의 지적만으로 고쳐지지 않는 반복 오류는 이번처럼 Program 규칙(B 키워드 필터)으로 옮겨야 한다.

## 5. 남은 문제

- 키워드 판정 범위: Program 후보 12건 중 Agent가 2건만 판정했다. 판정하지 않은 후보를 Program이 '판정 없음'으로 보고서에 남기는 처리가 필요하다.
- B 키워드 필터가 걸러내지 못한 후보: 목차(`- 합병, 분할, 자산양수도, 영업양수도`, `2. 대주주와의 자산양수도 등`), 2002년 연혁 1건('합병' 키워드 쪽), 제품 소개 문단('분할').
- 사실 누락·변동: 복잡 사례에서 실행마다 뽑히는 사실이 달라진다(최종 실행은 IPO 목적·정정일자·결의일 누락, 처분 후 지분 85.0%는 매번 누락).
- 사실 문장 오류: 복잡 F2의 자기자본 주어 오류처럼, 숫자는 맞고 주어·시점이 틀린 문장은 Program 대조로 잡히지 않는다.
- 보고서 작성 단계: 키워드 판정이 없는데 키워드 절을 지어냄(복잡), 확인 필요 항목의 접수번호 표시를 지워 같은 문장이 두 번 나옴(일반).
- 보고서 양식: 키워드 '아님' 표기가 항상 '(부정문)'으로 붙는 문제, '없음'인데도 데이터 출처 경고 줄 출력, 신뢰도 '판단 불가' 표기.
- 수치 보정 기록 문구: Program이 값을 확정하지 못한 경우를 "Program 값과 달라 바꿈"이 아니라 "확정 불가로 제외"로 구분해야 한다.
- 도구 미호출: gpt-4o-mini가 도구를 쓰지 않았다. 다른 모델이나 도구 사용 강제 옵션은 이번에 시험하지 않았다.
- 보고서 작성 단계 누락: 분석 결과에 있는 Program 추가 항목(일반 계약금액)을 보고서 작성 Agent가 빠뜨렸다. 보고서에도 대조가 필요하다.
- (해결) 같은 코드의 확인 필요 항목이 여러 건일 때 1건이 빠지던 보완 규칙을 항목 단위로 고치고 재실행해 16/16을 확인했다.
